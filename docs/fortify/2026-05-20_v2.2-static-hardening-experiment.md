- 字符串 / 常量 / 控制流 / 算术混淆；对 Retrofit、Gson 模型、Compose UI、OkHttp 等保留保守 keep 规则。

## 2. 备选方案 — **已启用诱饵凭证管线**

未使用 dProtect 时，新增三条与真实流程结构相同的 **AES-GCM 风格** 物料管线，使用 **不同的盐值格（salt lattice）** 与 **无效密文分片**（GCM 解密失败 → 返回 `null`）。命名中不使用 `fake` / `decoy` / `test` 等明显字样。

| 管线 | 包路径 | 作用 |
|------|--------|------|
| Archive | `security.credential.archive` | 静态干扰；解密失败 |
| Rotation | `security.credential.rotation` | 静态干扰；解密失败 |
| Standby | `security.credential.standby` | 静态干扰；解密失败 |
| Session（真实） | `SessionMaterialPipeline` | 构建期生成的 `MaterialSegment*` 分片 |

**入口：** `BootstrapCredentialRegistry.bootstrapTokenOrNull()` — `NetworkModule` 在 release 下通过它读取 bootstrap。

**解析逻辑：** Registry 先 warm 全部管线（`materialDigestPreview`），再依次调用各 `bootstrapTokenOrNull`。仅 `SessionMaterialPipeline` 能返回有效 token；它在列表 **末尾**，可覆盖前面管线偶发的非 null 结果。

`RuntimeCredentialProvider` 保留为薄封装委托，兼容旧调用点。

## 3. ProGuard / R8

已更新 `app/proguard-rules.pro`：

- 仅 keep `BootstrapCredentialRegistry`（不保留整个 credential 包的可读类名）。
- 对所有 credential 分片类型（生成类 + archive/rotation/standby）`keepclassmembers` 保留 `payload()`。
- `IntegrityChecker`、`SensitiveRequestGuardInterceptor` 使用 `-keep,allowobfuscation` 允许混淆类名。
- 保留 Retrofit / Gson / Kotlin metadata / `data.model.**` 等规则。
- 保留 `Application`、`MainActivity`、`ui.**`。

`app/build/outputs/apk/release/app-release-unsigned.apk`

安装与签名校验说明见 `docs/fortify/2026-5-20_chase-afterattack-fortify.md`。**不要**用 debug 签名 APK 测试 release 证书校验。

## 5. 静态检查（release 构建完成后）

```bash
APK=app/build/outputs/apk/release/app-release-unsigned.apk
# 或对 rebp 签名后的 APK 替换路径

# APK 中不应出现明文 bootstrap（若已知 key 前缀，可替换为短前缀再 grep）
unzip -p "$APK" classes*.dex | strings | grep -i 'Bearer' || true

# 凭证相关符号（R8 后可能仅剩少量类名；mapping 见 build/outputs/mapping/release/）
unzip -p "$APK" classes*.dex | strings | grep -E 'Material|Segment|Lattice' | sort -u | head -40
```

JADX：打开 release APK 后，应能看到多条 resolver/assembler 相关类型（`credential.archive`、`credential.rotation`、`credential.standby` 及生成的 `fragments`；R8 后类名可能已缩短，可对照 `mapping.txt`）。

## 6. 手动功能测试

1. 卸载旧包：`adb uninstall com.example.reverseengineeringbuildphase`
2. 安装 rebp 签名的 release APK。
3. 冷启动 → 点击 **Generate** → 应与 v2.2 之前一样成功。
4. 可选：签名校验失败时 `adb logcat -s REBP-Signing`（不记录 token）。

## 7. 运行时影响

- **预期：** rebp 签名 release 下，HTTPS 目标、证书固定（pinning）、API 行为与改前一致。
- **开销：** 解析 bootstrap 时会额外触碰 3 组分片（XOR digest + 失败解密），仅在读取 session/bootstrap 时执行，非每次 HTTP 请求。
