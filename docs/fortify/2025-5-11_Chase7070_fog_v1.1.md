# 开发日志 · 2026-05-11

**主题：** 开源 StringFog 接入（降低 JADX 静态字符串搜索命中率）  
**范围：** Gradle 插件与运行时依赖、自有包 `fogPackages`、R8/ProGuard keep、与既有 Retrofit/Gson 规则并存。  
**说明：** 本条为 **2026-05-11** 当日迭代记录；**不**改写 [2026-05-09.md](2026-05-09.md)（该文件保留为 5 月 9 日网络与出站策略加固日志）。

## 1. 目的（为何做）

- **课程目标：** COMPSCI 702 逆向作业语境下，在 **不做商业壳、不做重型反调试** 的前提下，提高通过 JADX「全文搜字面量」定位业务代码的成本。
- **技术目标：** 对 **应用自身包** 内编译进 dex 的 **字符串常量**（如 header 名、UI/异常中的路径提示、`BuildConfig` 注入值等）做 **编译期加密 + 运行期解密**，与既有 **R8** 共存。
- **明确不做：** 不声称解决 **Retrofit 注解路径**、**Gson `@SerializedName`** 的静态可见性；不替代服务端鉴权或 token 保密。

## 3. 怎么做的（实现要点）

1. **插件解析（`settings.gradle.kts`）**  
   Gradle Plugins DSL 使用 id `stringfog` 时，通过 `resolutionStrategy.eachPlugin` 将请求解析到 **`com.github.megatronking.stringfog:gradle-plugin:<version>`**，以便从 Maven Central 拉取（工程未将 StringFog 发布到 Gradle Plugin Portal 的默认解析路径）。

2. **`app/build.gradle.kts` 顺序与 classpath**  
   - `plugins { … id("stringfog") version "5.2.0" }` 满足 Kotlin DSL 对 `plugins {}` 置顶的要求。  
   - 在其后增加 **`buildscript { classpath("…:xor:5.0.0") }`**：上游插件在 **configuration** 阶段会对 `implementation` 配置的类名做 **`Class.forName`**；若 xor 仅写在 `dependencies` 里，类不在 **构建脚本类路径** 上，会报 **`StringFogImpl` not found**。  
   - `dependencies` 中增加 **`implementation("…:xor:5.0.0")`**：供 **APK 运行期** 解密。

3. **StringFog 扩展配置**  
   - `implementation = "com.github.megatronking.stringfog.xor.StringFogImpl"`  
   - `fogPackages = arrayOf("com.example.reverseengineeringbuildphase")`：**仅自有包**，不对第三方 AAR/JAR 做 fog。  
   - `kg = RandomKeyGenerator()`，`mode = StringFogMode.bytes`。  
   - `packageName` 显式为 `com.example.reverseengineeringbuildphase`（与 `namespace` / `applicationId` 一致；`AndroidManifest.xml` 无 `package=` 属性时，插件需能解析应用 id 以生成 `StringFog` 辅助类）。

4. **R8 / ProGuard**  
   在保留原有 Retrofit、Gson keep 的前提下，增加对 **生成的 `…StringFog` 类**、**`StringFogImpl`** 及 **`com.github.megatronking.stringfog.**`** 的 keep，避免 shrink 时拆掉解密调用链。

5. **与 5 月 9 日日志的关系**  
   StringFog **不属于** 2026-05-09 当日「网络安全与出站策略」变更范围；故 **单独**使用本文件记录，避免污染历史日期日志。

## 4. 如何检测（验证清单）

### 4.1 构建

```bash
./gradlew :app:assembleDebug
./gradlew :app:assembleRelease
```

两者应 **BUILD SUCCESSFUL**；Release 应仍执行 `minifyReleaseWithR8`、`transformReleaseClassesWithAsm`（或等价任务名，视 AGP 版本而定）。

### 4.2 功能回归（真机 / 模拟器）

- 配置有效 `secrets.properties` 后走通：**prompt → `/auth` → `/generate_image` → 预览 → 保存相册**（与 README 主流程一致）。

### 4.3 静态效果（作业报告向）

- 用 **JADX** 打开 `app/build/outputs/apk/release/` 下 **release APK**（未签名包名以实际输出为准）。  
- 在 **自有代码类**中搜索：如 `Authorization`、自定义错误文案中的路径片段等；对比接入前是否仍大量以 **明文 `ldc`/常量** 出现。  
- 命令行辅助（注意 **OkHttp 等依赖** 中可能仍含 `authorization` 等通用字面量，需结合 **命中类包名** 判断）：  

```bash
unzip -p app/build/outputs/apk/release/<你的release.apk> classes.dex | strings | grep -i authorization
```

### 4.4 预期仍可见（用于报告「边界」）

- **`@POST("auth")` / `@POST("generate_image")`** 等 Retrofit 注解参数。  
- **`@SerializedName("…")`** 中的 JSON 字段名。  
- 依赖库内与 HTTP 规范相关的字符串。

## 5. 风险与已知限制

| 风险 | 说明 |
|------|------|
| **Gradle / AGP 升级** | StringFog 依赖 AGP Instrumentation API；上游曾标注与 **Gradle 9** 部分路径的兼容性 TODO。当前仓库若使用较新 Gradle，升级后需 **重新打 Release 全量回归**。 |
| **Debug 与 Release 均 instrument** | 当前上游逻辑对 **各 variant** 生效；**并非**「仅 Release 加密」。Debug 包同样经过字符串变换，调试时若对比 smali/dex 需有心理预期。 |
| **密钥仍在客户端** | 仅提高 **静态阅读/搜索** 成本；动态调试、抓包、内存仍可取回明文语义。 |
| **ProGuard keep 范围** | 对 `com.github.megatronking.stringfog.**` 的 keep 偏宽，有利于稳定；若极度在意 dex 体积可后续收窄（需实测）。 |
| **维护与 Issue 响应** | 上游 README 说明维护精力有限；遇 AGP 破坏性变更需自行查 issue / 锁版本。 |
