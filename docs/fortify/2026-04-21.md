## 1. Release 启用 R8 / ProGuard + 资源收缩

**修改**

- `app/build.gradle.kts`：`release` 中 `isMinifyEnabled = true`，`isShrinkResources = true`；`debug` 未改。
- `app/proguard-rules.pro`：补充最小 keep 规则（Retrofit 接口 HTTP 注解、`@SerializedName` 字段、注解相关 `-keepattributes`）。

**为什么**

- 课程允许使用 Android 官方 R8/ProGuard 提高静态分析与反编译阅读成本。
- Retrofit / Gson 依赖运行时代码与注解信息，缺规则易导致 release 崩溃，故只保留必要 keep。

**作用**

- 提高 APK 内类名/方法名混淆程度，增大逆向门槛。
- 移除未使用资源，缩小 release 包体。
- 仅作用于 `release`，不影响日常 `debug` 开发与 emulator 演示。

---

## 2. Release 下收敛网络日志（OkHttp Logging）

**修改**

- `app/src/main/java/.../data/network/NetworkModule.kt`：仅在 `BuildConfig.DEBUG == true` 时添加 `HttpLoggingInterceptor`（`Level.BASIC`）；`release` 不再注册该拦截器。其余出站拦截器（白名单、GET Content-Type）见 **第 4 节**。

**为什么**

- `HttpLoggingInterceptor` 会向 logcat 输出请求方法、URL 等，便于开发调试，但在 release 会降低动态分析门槛并可能泄露接口细节。

**作用**

- `release` 安装包运行时不再通过 OkHttp 打印网络请求日志，降低信息暴露。
- `debug` 仍保留原有日志行为，便于本地联调。

---

## 3. Manifest：`allowBackup=false`、禁止明文、网络安全配置

**修改**

- `app/src/main/AndroidManifest.xml`：`android:allowBackup="false"`；`android:usesCleartextTraffic="false"`；`android:networkSecurityConfig="@xml/network_security_config"`；`android:name=".ReverseEngineeringApp"`。
- `app/src/main/res/xml/network_security_config.xml`：`base-config` 仅信任 **system** CA、禁止 cleartext；`debug-overrides` 在 **debuggable** 构建下额外信任 **user** CA（便于本地抓包），**release** 不应用 overrides，从而不信任用户安装 CA。

**为什么**

- 关闭备份减少通过 `adb backup` 导出应用数据的攻击面。
- 显式禁止明文 HTTP，与 NSC 一致收紧传输策略。
- Release 不信任 user CA，降低被中间人解密 HTTPS 的风险；开发构建仍可用 Charles 等工具。

**作用**

- 系统层统一约束 TLS 与明文策略；与 OkHttp 层白名单互为纵深。

## 4. Host 白名单 + 图片 URL 校验 + GET Content-Type

**修改**

- `AllowedHosts.kt`：从 `BuildConfig.BASE_URL` 解析 host，并合并可选 `BuildConfig.ALLOWED_NETWORK_HOSTS`（`secrets.properties` 中逗号分隔、无 scheme）。
- `HostAllowlistInterceptor.kt`：出站请求 host 必须在白名单内。
- `ImageUrlValidator.kt`：要求 **HTTPS** 且 host 在白名单；`/generate_image` 返回 URL 经校验后才交给 UI。
- `ImageGetContentTypeInterceptor.kt`：对 **成功** 的 **GET** 响应校验 `Content-Type` 主类型为 `image`（避免把非图片响应当图片解码）。
- `NetworkModule.kt`：共享 `okHttpClient` 供 Retrofit、Coil、`ImageSaver` 使用；拦截器顺序：白名单 → 鉴权 →（debug 日志）→ Content-Type。
- `ReverseEngineeringApp.kt`：实现 Coil `ImageLoaderFactory`，全局 Coil 使用上述 `okHttpClient`。
- `ImageSaver.kt`：改为通过 OkHttp GET 下载字节，不再使用 `java.net.URL.openStream()`（避免绕过 OkHttp 策略）。
- `app/build.gradle.kts`：注入 `ALLOWED_NETWORK_HOSTS` BuildConfig 字段。
- `GenerateImageFailure.InvalidImageUrl` + `MainViewModel` / `ImageRepository` 错误分支。

**为什么**

- 即使服务端异常返回恶意跳转 URL，客户端仍拒绝非白名单 host 与非 HTTPS。
- Content-Type 校验降低「返回 HTML/JSON 却被当图片处理」的风险。

**作用**

- API、Coil 预览、保存相册三条路径共享同一 TLS 与域名策略。

## 验证建议（可选）

- Release：`./gradlew :app:assembleRelease`，确认生成 `mapping.txt` 与 APK。
- 功能：保持 `/auth` → `/generate_image` → 显示图片 → 保存相册 主流程可用。
- **Logcat（release 包）**：确认无 token、无完整敏感响应体打印；除 debug 下 OkHttp `BASIC` 外无冗余网络日志。
- **静态分析 APK**：对 release APK 使用 JADX / `strings` / apktool，记录 `BuildConfig` 与残留字符串（作业报告用）；说明白名单与 NSC 为纵深缓解。
- **多 CDN host**：若图片与 API 不同域，在 `secrets.properties` 设置 `ALLOWED_NETWORK_HOSTS`（逗号分隔）。
